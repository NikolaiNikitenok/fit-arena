# Контент через локальный Codex

Команды администратора бота: `/reel [тема]`, `/talk [тема]`, `/carousel tips|app [тема]`,
`/story [тема]`, `/loop [тема]`. Существующие кнопки работают так же.
`/content` показывает очередь и доступность компьютера. `/content codex` включает
локальные сценарии; `/content claude` возвращает прежний генератор для новых заданий.
Уже принятые задания продолжают обрабатываться.

## Как это работает

1. Arena сохраняет задание в `data/content-jobs` на VPS. Доступ — только администратору.
2. Обработчик Windows через существующий SSH-ключ забирает одно задание с арендой на 15 минут.
3. `codex exec` с сохранённым входом ChatGPT пишет сценарий и подпись, без API-ключа.
   Команды модели не требуются; запуск использует read-only sandbox и отдельную временную папку.
4. Сценарий проверяется теми же правилами, что и в существующем сборщике.
5. VPS передаёт подготовленный JSON в GitHub Actions. Генератор распознаёт его и
   **пропускает обращение к Claude**, затем прежняя озвучка и монтаж создают файлы.
6. Бот присылает видео/картинки и подпись в тот чат администратора, который запустил задание.

Задания переживают перезапуск сервера и отсутствие компьютера. Прерванная работа
возвращается в очередь после истечения аренды; старый обработчик не может завершить
уже перехваченное задание. Неопределённый результат запроса к GitHub после сбоя
автоматически не повторяется, чтобы не создать дубликат: бот предлагает проверить Actions.
Лимит очереди — 12 ожидающих/активных заданий. Во время исчерпания лимитов Codex
бот сообщит об ошибке; можно повторить позднее или переключиться на Claude.

## Установка

На VPS от root установить `queue_bridge.py` как `/usr/local/sbin/arena-content-queue.py`
с правами `700`. Каталог `/opt/arena-server/data/content-jobs` — `deploy:deploy`, `700`.
`CONTENT_PROVIDER=codex-local` в `/etc/arena-server.env` задаёт начальный режим.
Явно выбранный `/content` режим хранится в `provider.json` и имеет приоритет.
Архивы резервирования runtime включают очередь вместе с остальными данными Arena.

На Windows проверить `codex login status` (должен быть ChatGPT), SSH к серверу и выполнить:

```powershell
& .\promo\content\install-worker.ps1
```

Планировщик Windows запускает скрытый обработчик при входе текущего пользователя.
Компьютер должен быть включён, пользователь должен войти в Windows; в спящем режиме
генерация ждёт пробуждения. Файлы настроек, сценарии и журнал находятся в
`%USERPROFILE%\.codex\content-worker` с доступом текущему пользователю и SYSTEM.
`worker.log` не содержит токенов, полного текста сценариев или Telegram ID.
Задание планировщика: `Nikitenok Content Worker`. Для разовой проверки при
остановленном обработчике:

```powershell
node .\promo\content\worker.mjs "$env:USERPROFILE\.codex\content-worker\settings.json" --once
```

Учётные данные ChatGPT остаются в обычном локальном хранилище Codex, на сервер и
GitHub не копируются. `OPENAI_API_KEY`/`CODEX_API_KEY` из окружения не передаются
процессу генерации. Используются лимиты Codex текущей подписки. Сборка расходует
минуты GitHub Actions и использует существующую озвучку; это отдельные внешние сервисы.
Генерация новых изображений или видео через OpenAI API в этот обработчик не включена.

## Качество и следующие шаги

Первый формат — реальный геймплей с действием в первые две секунды, одним понятным
конфликтом, доказательством в кадре и одним призывом. Сценарий не должен выдумывать
отзывы, личные достижения, статистику или обещать бесплатность всех PRO-функций.
Подпись дополняет видео. Гарантировать вирусное распространение нельзя.

Позднее: отдельные описания для Shorts/TikTok/Instagram; явное подтверждение публикации;
подключение аккаунтов через разрешённые платформами способы; журнал отправок и
защита от повторной публикации; сравнение удержания и первых секунд разных выпусков.
Автопубликация сейчас не включена. Для персонажей уже есть 3D-рендер; Blender можно
подключить как дополнительный сборщик без переноса тяжёлого рендера на маленький VPS.

Дата: 2026-11-05 (Москва). Исходный commit: `eeb0fc0`. Работа только локально, без деплоя, production API/БД и пользовательских данных.

## Восстановление сессии

Рабочая область: `../arena-modernization`, ветка `codex/arena-modernization` репозитория fit-arena. Исходная копия fit-arena была чистой на main. Родительский ecosystem — другой Git-репозиторий с untracked каталогами; он не изменялся. Создан отдельный git worktree. Зависимости доступны через junction node_modules на существующую установку fit-arena; npm ci не запускался и lockfile не менялся.

Активная отдельная сессия «Изучить архитектуру 3D-героев» обнаружена через список чатов. Ее файлы/ветка/модели не менялись; интеграция будущих героев требует отдельного переноса и визуальной проверки. Ничего не отправлять в main: README указывает автоматический production deploy при push в main.

## Этап 0: архитектура и исходная контрольная точка

React 19/Vite/Three.js Mini App в src; Telegram bridge и браузерная авторизация; Node/HTTP/WebSocket API в server/index.ts. ID — отдельный сервис с SQLite, игровое состояние Arena — JSON-хранилища, локальный Progress и синхронизация savedAt. Камера: MediaPipe lite/WASM с собственного origin, GPU с CPU fallback, useRepCamera → RepCounter/PlankTimer → MissionPlay/WorkoutSession/Duel/Raid/Event. Калибровка в calibration.ts. Обучение: IntroChat/Onboarding, выбор Спорт/Приключение, тренер и история; повтор инструкции доступен из настроек. Награды: progress/resources; соревнования: rooms/clans/wars/cities/guard. Аналитика: telemetry → собственный endpoint, statsPage/admin. Подробные зависимости и риски: modernization-systems-audit.md.

База: npm test — 106 файлов PASS, 896 PASS, 2 SKIP (Windows shell fixtures), 12.30 s. npm run build — PASS, Vite 1.44 s (без времени tsc). Крупные chunks: index 681.83 kB (gzip 230.12), Canvas3D 926.20 kB (gzip 247.46). Это размер сборки, а не скорость запуска телефона. Предупреждения dynamic/static imports и chunks >500 kB уже были до изменений. Замеров FPS/памяти реального телефона нет.

План риска: сначала устранить гонки камеры и ложные повторения, затем readiness/countdown с отключаемым флагом; проверить через независимый QA и hook harness; расширить только минимальную аналитику; отдельно воспроизвести серверные риски наград. Без изменения баланса, порогов амплитуды, сохранений, моделей или формата инвентаря. Не заменять клиентскую камеру заявлениями о серверном доказательстве упражнения.

## История проверок и ошибок

- Начальная попытка npm test в новом worktree не нашла vitest: зависимости не были подключены. Junction с относительным target Windows отказался создавать; подключение с Resolve-Path исправило среду. После этого базовый suite прошел.
- Независимый QA воспроизвел ошибки стороны/потери человека/опоры планки до исправлений. 4 целевых файла: 75 PASS после исправлений.
- Независимый review выявил первоначальные недочеты интеграции: probe первого упражнения после switch, отсутствующий COMPLETED, перезапись ERROR после первичного кадра, stale go в дуэлях, слишком жесткий gap250мс. Исправлены; gap теперь параметр конструктора750мс, cadence300мс тестируется.
- Полный промежуточный suite: 110 файлов PASS/1 FAIL, 4 ошибки из-за mock telemetry во время параллельного обновления тестов. Это ошибка интеграции тестового harness; новые реальные проверки reporter добавлены, suite запускается заново. Не считать этот запуск успешным.
- Vite dev с junction выдал403 на шрифты вне разрешенного root. Ограничения не ослаблялись; браузерный smoke перенесен на локальный production preview со встроенными assets.

## Откат и продолжение

Флаг `VITE_POSITIONING_GATE=0` перед npm run build отключает новый managed countdown/readiness для быстрого сравнения. `VITE_POSITIONING_STABLE_MS=1000..2000` настраивает стабильность, default1500. Исправления распознавания/cleanup и серверная аналитика остаются отдельными изменениями, полный откат — git revert соответствующих локальных коммитов в обратном порядке. Сохранения/скины/ID/DB схемы не менялись, обратная миграция не нужна. Не применять reset --hard в исходной общей копии.

Далее: дождаться 3D, закрыть сценарии из modernization-manual-checks.md, реализовать совместимый claim protocol, закончить аналитику/admin и полный E2E. Не объявлять готовность, пока остаются эти FAIL/BLOCKED/WAITING.

# Воспроизводимые оставшиеся проверки

Использовать отдельный тестовый аккаунт и локальное/staging окружение, отдельные test data directories; production не применять.

1. **Камера и запуск (iOS Telegram, Android Telegram, обычный mobile browser).** Записать ОС, устройство, WebView, версию сборки. Открыть первое испытание: 10с без человека — время уровня не уменьшается; показать только ненужные суставы — старта нет; показать необходимые для выбранного упражнения — 1.5с устойчивости, readiness,3–2–1. Сломать позу на2 — новый countdown только после устойчивости. Проверить повтор для pushup/squat/situp/plank, поворот телефона. Планка: считаются секунды, без опоры не считает.
2. **Прерывания.** Отменить во время model load, запроса permission и video.play; разрешить поздно — камера должна погаснуть. Сразу запустить снова — старый поток не мешает. Отказать камере → понятная ошибка → Назад/Ещё раз. Для retry выдать разрешение в настройках браузера. Ошибка inference должна открыть существующий экран ошибки. Свернуть на10с во время подготовки — прошлый кадр не завершает готовность; во время рейтингового боя дедлайн остается исходным.
3. **Повторы.** Полное движение, неполное, быстрое/медленное, граница порога, дрожание, выйти в нижней фазе и вернуться в верхнюю — невидимая часть не засчитывается. Повторять для видимой справа/слева стороны. Записывать только обезличенные результаты/ожидания. Реальные видео/координаты не собирать без отдельного согласия; разрешенные синтетические fixtures находятся в repCounter.test.ts/plank.test.ts. Для корпуса реальных размеченных видео нужны отдельные основания и условия хранения; до него не заявлять проценты точности.
4. **Полный первый путь.** Новый тестовый профиль → тренер → оба направления → герой → камера → readiness → countdown → реальное упражнение → награда → энергия → dungeon/match3 → ресурсы → главный экран → закрыть/открыть. Проверить сохранение героя/облика/монет/заряда. Посчитать число нажатий до первой награды отдельно для каждого направления. Повторить без сети и после отказа камеры. До первой физически подтвержденной награды текущий browser smoke не заменяет эту проверку.
5. **Награды.** Сценарии claimDelivery.test.ts воспроизводят потерю ответа и ограниченность client dedupe. Для будущего receipt решения: потерять ответ до/после клиентского save, crash до/после flush, retry в другом устройстве/старом snapshot, replay чужого ключа, legacy claim без receipt, двойной request. Требование: ровно одно начисление и восстановление подтвержденной выплаты. Текущее решение НЕ проходит восстановление.
6. **3D.** После отдельной сессии интегрировать в тестовую ветку рыцаря/мага/варвара; Blender export GLB, skeleton/animations/materials, лица/пропорции, автооборот главного экрана, примерочная, старые купленные skins, mobile GPU, WebGL lost/restored. Старые assets сохранить до приемки.
7. **Производительность.** На устройствах измерить cold/warm load, JS heap, active GPU contexts, FPS/p95 inference, память до/после10 запусков, фон/возврат, плохую сеть. Сравнить 3D+CV с камерой отдельно и lowPower15fps. Все tracks должны ended после выхода. Browser preview не является проверкой телефона.
8. **Аналитика.** Проверить тестовую сессию до камеры/после отказа/с потерей трекинга/с завершением; в пакетах sid/at/v/id и allowlist metadata, нет имени/id Telegram/landmarks. После будущей админки сравнить numerator/denominator, когорты D1/D7 и platform/version; old aggregate counts нельзя выдавать за последовательную session funnel.

Для подготовки релиза обязательны устранение потери наград, завершение аналитики и полного E2E, независимый review финального diff и подтверждение перечисленных устройств. Эти шаги не выполнены автоматически данным журналом.
